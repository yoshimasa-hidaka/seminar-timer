# 研究会 講演タイマー / Seminar Talk Timer

**日本語** | [English](README.en.md)

研究会やセミナーの講演時間を測るタイマーです。PC（Mac・Windows・Linux）で起動し、iPad に残り時間を大きく表示して、PC から操作します。追加のパッケージは要りません（Node の標準ライブラリだけ）。外部に通信せず、オフラインで動きます。

iPad ですぐ試すなら、公開ページ [https://yoshimasa-hidaka.github.io/seminar-timer/solo.html](https://yoshimasa-hidaka.github.io/seminar-timer/solo.html) を Safari で開いてください（ホーム画面への追加は下の「iPad 単体モード」）。

---

## 2つのモード

用途に合わせて2通りの使い方があります。

| モード | 構成 | ネットワーク | 向いている場面 |
|---|---|---|---|
| ① 2台同期 | PC（Mac・Windows・Linux）で起動し、iPad に表示・PC で操作 | PC と iPad が同じ LAN にいること | iPad を聴衆に向け、手元の PC で操作したいとき |
| ② iPad 単体 | iPad 1台で表示も操作も行う | 起動時は不要。iPad への導入時だけ一度必要 | 接続の手間を省きたい、機材を iPad だけにしたいとき |

② は iPad に PWA（ホーム画面アプリ）として入れて使います。最初に一度 Safari で開いて「ホーム画面に追加」すれば、あとはオフラインで起動できます。Android・Windows・Mac のブラウザなら、単一ファイルの `seminar-timer-ipad.html` を開くだけでも使えます。② では操作と表示が同じ画面になります。

## 使い方（① 2台同期）

1. 起動します。Mac は `start.command`、Windows は `start.cmd` をダブルクリック、Linux は `start.sh` を実行します（ターミナルならどの OS でも `node server.js`）。
2. PC のブラウザに操作画面が開きます（開かないときは起動ログに出る `http://localhost:8080/control` を手で開きます）。画面の上部に iPad 用の URL と QR コードが出ます。
   - Windows では初回に「Windows セキュリティの重要な警告」が出ます。**「プライベート ネットワーク」と「パブリック ネットワーク」の両方にチェック**して「アクセスを許可する」を押してください。会場の Wi-Fi はパブリック扱いのことが多く、片方だけだと iPad から繋がりません。
3. iPad で QR を読む（または URL を入力）と表示ページが開きます。一度画面をタップすると音声が有効になり、全画面になります。
4. PC と iPad は同じ Wi-Fi につなぎます。会場の Wi-Fi が無いときは PC か iPad のテザリングを使います（下の「オフライン・接続について」）。

iPad から繋がらないときは、操作画面の QR の下に出る別の IP を試してください（PC に仮想ネットワーク（WSL・Hyper-V・VirtualBox・VPN など）があると候補が複数になります。サーバはもっともらしい順に並べますが、外すことがあります）。

ポート 8080 が使われていると、自動で 8081… に切り替わります。実際のポート番号は起動ログと操作画面で確認できます。

## iPad 単体モード（② PWA）

iPad の Safari で [https://yoshimasa-hidaka.github.io/seminar-timer/solo.html](https://yoshimasa-hidaka.github.io/seminar-timer/solo.html) を開き、共有メニューから「ホーム画面に追加」してください。次からはホーム画面のアイコンで起動し、会場でも完全にオフラインで動きます。

起動したら一度画面をタップして音声を有効にします。画面の下半分で、開始・一時停止、手動ベル（🔔1/🔔2/🔔3）、プリセット、予鈴などを操作します。PC のブラウザで使うときは 🖥 ボタンで表示専用ウィンドウが開くので、それをプロジェクタ側の画面に置いて全画面にし、手元のウィンドウで操作できます（サーバ不要・同じブラウザ内で同期。音は手元のウィンドウから鳴ります）。進行中はこの操作行までを残してパネルが縮み、タイマーが大きく表示されます。その下の設定はスクロールで出せます。持ち時間・予鈴・ベル音・プリセットなどの設定は iPad の中（localStorage）に保存され、次回も復元されます。

## はじめての人へ（① を渡す・受け取るとき）

① の 2台同期版は PC の Node.js で動きます（② の iPad 単体 PWA は Node を使いません）。① を受け取った人は、最初に一度だけ次を確認してください。

- 共通：Node.js を入れます。入っていなければ起動スクリプトが案内を出します（古いとバージョンの警告も出ます）。[nodejs.org](https://nodejs.org/) の LTS 版を入れて、もう一度起動してください。終了するときは、起動した黒いウィンドウで `Ctrl + C` を押すか、ウィンドウを閉じます。
- Mac：
  1. 「開発元を確認できない」と出たとき（ダウンロードやメール、AirDrop で受け取ったファイルに付く保護です）は、`start.command` を右クリックして「開く」を選び、続けて出る確認ダイアログでもう一度「開く」を押します（初回だけ）。
  2. ダブルクリックでテキストエディタが開くとき（zip 展開で実行権限が外れた場合）は、ターミナルで `chmod +x start.command` を実行するか、上の右クリック→開くで起動します。
- Windows：
  1. `start.cmd` をダブルクリックします。「Windows によって PC が保護されました」と出たら「詳細情報」→「実行」を押します（初回だけ。ダウンロードした zip に付く保護です）。
  2. 続けて出る Windows ファイアウォールの警告では、プライベート・パブリックの両方にチェックして許可します（上の「使い方」の 2）。
  3. `start.cmd` の表示は英語です（コマンドプロンプトは UTF-8 の日本語を安定して表示できないため）。内容はこの README と同じです。
- Linux：ターミナルで `bash start.sh` を実行します（ファイルマネージャから起動するなら `chmod +x start.sh` のうえ「端末で実行」）。

フォルダごと zip にして渡すのが簡単です（macOS のアーカイブユーティリティで展開すれば実行権限は保たれます）。

## 機能

### タイマー（2フェーズ）
- 講演と質疑応答を分けて管理します（例：講演20分＋質疑10分）。
- 講演時間が来ると自動で質疑に移ります。早く終わったときは「質疑応答へ」で手動でも移れます。
- iPad に現在のフェーズ（講演／質疑応答）と残り時間を大きく表示します。
- 大きい数字を押すと、現フェーズの残りと全体（質疑込み）の残りを切り替えられます（iPad と操作画面で同期）。
- 実行中は終了予定の時刻も表示します（例：終了予定 14:35）。

### 鈴（ベル）
- 予鈴は講演終了の数分前に鳴らせます。予鈴1・予鈴2 の2回まで設定でき（例：5分前と1分前）、予鈴2は既定でオフです（0で無効）。
- 講演終了で2鈴、質疑終了で3鈴（全体終了）が鳴り、以降は赤の点滅で超過を表します。
- 色は緑（通常）→黄→赤＋点滅（超過）と変わります。黄になるのは、講演では予鈴の残り時間以下、質疑では残り60秒以下のときです（質疑はベルを鳴らさず色だけ変わります）。
- 手動ベルとして、操作画面（① PC）と iPad 単体版（②）の 🔔1／🔔2／🔔3 をいつでも鳴らせます。

### ベル音（合成・音声ファイル不要）
- 音色は 11 種類から選べます（選ぶとその場で試聴します）：卓上ベル（タイムキーパーの呼び鈴「チーン」・既定）／タイマー（キッチンタイマー風「ピピピピ」）／目覚まし（ピロピロ）／学校チャイム（キーンコーンカーンコーン）／ピンポーン／チャイム／ベル／ゴング／木琴／ビープ／ブザー。1鈴・2鈴・3鈴は、卓上ベル・タイマー・目覚まし・ゴング・ブザーでは回数、学校チャイムでは節の数（1〜3 節）になります。
- 音量とピッチ（高さ）をスライダーで調整できます。ピッチは半音単位で −12〜+12（1 オクターブ下〜上）、現在値を表示し、ダブルクリック（iPad はダブルタップ）で標準に戻ります。
- 2鈴・3鈴で打つ間隔もスライダーで調整できます（音色ごとの基準間隔の 0.5〜3 倍。選択中の音色での秒数を表示し、離すと 2鈴で試聴します）。
- ① では iPad の音と PC の音を別々にオン/オフできます（PC を会場スピーカーにつなぐ運用などに対応。② は音のオン/オフが1つです）。

### メッセージ
- PC から「あと5分」などを iPad の画面上部に大きく表示できます（定型文と自由入力）。
- 表示中のメッセージは操作画面にも出るので、消し忘れを防げます。

### 操作画面（PC）
- プリセット（例：10+5 / 15+5 / 25+5 / 30+10 / 45+15）をワンタップで適用できます。詳細設定の「プリセット編集」で、講演・質疑・予鈴1・予鈴2 の分数を直接書き換えられ、追加・削除もできます。
- 時間の設定はその場で反映します（入力欄と −／＋ ステッパー）。
- キーボード操作：スペースで開始/一時停止、R でリセット、Q で質疑へ、T で講演へ、←/→ で ±10秒、↑/↓ で ±1分。
- 誤操作を防ぐため、進行中は時間設定とリセットを無効にし、プリセットの削除には確認を挟みます。
- 日本語／English を切り替えられます（操作画面・iPad 表示・メッセージが連動）。

### iPad 表示
- 画面のスリープを防ぎます（Screen Wake Lock・iPadOS 16.4 以降）。確実にしたいときは端末の自動ロックを「なし」にしてください。
- ホーム画面に追加すると Safari の UI が消えて全画面になります。

### PC のスリープ防止（①）
PC がスリープするとサーバが止まり、タイマーも止まります。
- Mac：`start.command` が `caffeinate` でスリープを抑止します（終了で自動解除）。
- Linux：`start.sh` が `systemd-inhibit` でアイドル・スリープを抑止します（systemd 環境。画面の消灯まで止まるかはデスクトップ環境によります）。
- Windows：起動スクリプトでは抑止できません。操作画面を Chrome か Edge で表示したままにすると画面は消えません（Wake Lock）。確実にしたいときは「設定 → システム → 電源」でスリープを「なし」にしてください。

### 設定の保存
- ① では、持ち時間・予鈴・ベル音/音量/ピッチ・iPad音・プリセット・言語・表示スコープを `config.json` に自動保存し、再起動しても復元します（進行中の時計は保存しません）。`config.json` は端末ごとのローカル設定で、リポジトリには含めません。
- ② では、同じ設定を iPad の localStorage に保存します（こちらも端末ごとで、次回復元します）。

## オフライン・接続について（① の PC↔iPad 接続）

この節は ① で PC と iPad をつなぐ話です。② の iPad 単体は、最初の導入を除いてネットは要りません。

外部には一切アクセスしません（CDN・外部フォント・外部 API を使わず、QR もその場で生成します）。ネットの無い会場でも動き、必要なのは PC と iPad の間のローカル通信路だけです。

会場の Wi-Fi が無い・使えないときは、外部ネット無しで2台だけの閉じた Wi-Fi を作ります。

- 方法1（Mac）：Mac を親機にする（おすすめ）
  1. システム設定を開きます（左上のアップルメニュー →「システム設定…」）。
  2. 左の一覧から「一般」→「共有」を選びます。
  3. 「インターネット共有」の行の ⓘ ボタンを押し、「相手との接続方法」を「Wi-Fi」にします。「Wi-Fi オプション…」でネットワーク名とパスワード（WPA2）を設定して「OK」を押します。
  4. 「インターネット共有」のスイッチをオンにします（確認ダイアログは「開始」）。
  5. iPad の 設定 →「Wi-Fi」で、いま作った Mac の Wi-Fi を選んで接続します。
  - ネット接続が無くても機能します（Mac の IP が `bridge100` などになってもサーバが自動で検出し、URL/QR に反映します）。
- 方法1（Windows）：Windows を親機にする
  1. 「設定 → ネットワークとインターネット → モバイル ホットスポット」を開き、ネットワーク名とパスワードを確認（必要なら編集）して、スイッチをオンにします。
  2. iPad の 設定 →「Wi-Fi」で、そのネットワークに接続します。
  - Windows のホットスポットは、PC がインターネットに繋がっていないとオンにできないことがあります。その場合は方法2（iPad を親機）を使ってください。
  - ホットスポット側の IP は `192.168.137.1` になります。PC が会場 Wi-Fi にも繋がっていると、操作画面にはそちらの IP が先に出るので、QR の下で `192.168.137.1` に切り替えてください。
- 方法1（Linux）：Linux を親機にする
  - GNOME なら「設定 → Wi-Fi → 右上のメニュー → Wi-Fi ホットスポットをオンにする」。他のデスクトップ環境は NetworkManager のホットスポット機能を使います（`nmcli device wifi hotspot` でも作れます）。
- 方法2：iPad を親機にする（セルラー対応の iPad のみ。Wi-Fi モデルにはこの機能がありません）
  1. iPad の 設定 →「インターネット共有」を開きます（出ないときは 設定 → モバイル通信 → インターネット共有）。
  2. 「ほかの人の接続を許可」をオンにし、表示される Wi-Fi のパスワードを控えます。
  3. PC の Wi-Fi 一覧から iPad を選んで接続します。
- 会場の Wi-Fi があっても、AP isolation（端末間の通信を遮断する設定）だとつながらないことがあります。その場合も方法1・2 を使ってください。
- Windows で iPad から繋がらないときは、ファイアウォールで Node.js が許可されているか確認してください（「Windows セキュリティ → ファイアウォールとネットワーク保護 → ファイアウォールによるアプリケーションの許可」で Node.js のプライベート・パブリック両方にチェック）。

OS のバージョンによって項目名が少し違うことがあります（古い macOS は「システム環境設定 →共有 →インターネット共有」）。見つからないときは設定の検索窓に「インターネット共有」「モバイル ホットスポット」と入れてください。

iPad で表示ページを開いたら、一度画面をタップしてください（このタップで音声が有効になります）。音が鳴らないときは、端末の音量と消音（コントロールセンターのベルマーク）も確認してください。

## 開発者向けメモ

ここから下は、リポジトリを fork して自分で配る・中身に手を入れる人向けです（ふつうに使うだけなら読まなくて構いません）。

### 自分でホスティングする（iPad のオフライン PWA）

iPad でオフラインの PWA にするには HTTPS が必要です。Service Worker は HTTPS（と localhost）でしか動かないため、PC サーバの平文 HTTP（`http://<IP>:<ポート>/solo`）からホーム画面に追加してもオフラインにはなりません。無料で HTTPS にするなら GitHub Pages が手軽です。

1. このリポジトリを GitHub に push します。
2. Settings → Pages で Source を「GitHub Actions」にします（同梱の `.github/workflows/pages.yml` が `public/` を配信します）。
3. 初回は、Pages を有効にする前に Deploy が走って失敗していることがあります。その場合は Actions タブで「Deploy PWA to GitHub Pages」を再実行してください。数分で `https://<ユーザー名>.github.io/<リポジトリ名>/` が公開され、以降は push のたびに自動で更新されます。

なお iPad では、ローカルの `.html` ファイルを直接開く方法は使えません（ファイルアプリの簡易プレビューになり、JavaScript・音声・保存が無効になります）。単一ファイルの `seminar-timer-ipad.html` は、ローカル HTML を実行できる Android・Windows・Mac のブラウザ向けです。

### 動作確認・ビルド

- 単体モードを手元で確認したいときは、サーバ起動中に `http://localhost:<ポート>/solo`（iPad からは `http://<IP>:<ポート>/solo`）を開きます。この経路ではオフライン化はされません。
- 2台同期版（①）と iPad 単体版（②）は同じ状態機械（`public/timer-core.js`）を使うので、タイマー・予鈴・自動移行の動きはどちらも同じです。
- 単一ファイル版 `seminar-timer-ipad.html` は `public/solo.html`・`timer-core.js`・`bell.js` から `node build-solo.js` で生成します。アイコンは `node make-icons.js` で作り直せます。
- テストは `node test/platform.test.js`（LAN IP の推定・OS 別コマンドの解析）、`node test/bell.test.js`（全音色の発音スケジュール・許可リスト）、`node test/server.smoke.js`（サーバ起動・配信・SSE・コマンド）。同梱の `.github/workflows/test.yml` が push ごとに Linux・Windows・macOS の 3 OS で両方を回します。

### 構成

| ファイル | 役割 |
|---|---|
| `server.js` | HTTP + SSE サーバ（① 2台同期。状態を一元管理し、設定を保存） |
| `platform.js` | OS に依存する部分だけを隔離（LAN IP の推定・既定ブラウザの起動・OS 別の起動時の注意）。Mac / Windows / Linux の違いはここに閉じる |
| `start.command` / `start.cmd` / `start.sh` | ダブルクリック起動（Mac / Windows / Linux）。Node の有無を確認し、Mac と Linux ではスリープも抑止 |
| `test/` | 単体テストと起動確認（`.github/workflows/test.yml` が 3 OS で実行） |
| `public/timer-core.js` | 状態機械の本体（tick・コマンド・予鈴・自動移行）。server.js と solo.html が共用し、同じロジックを二重に持たない |
| `public/control.html` | PC 操作画面（① 用） |
| `public/display.html` | iPad 表示画面（① 用） |
| `public/solo.html` | iPad 単体モード（② 表示＋操作を1ページに・PWA） |
| `public/index.html` | ② の配信ルート入口（Pages などでルートを開くと solo へ転送） |
| `public/manifest.webmanifest` | PWA マニフェスト（ホーム画面追加・アイコン・全画面） |
| `public/sw.js` | Service Worker（② をオフライン起動させるキャッシュ） |
| `public/icon-512.png` ほか | PWA／ホーム画面アイコン（`make-icons.js` で生成） |
| `public/bell.js` | ベル音の合成（WebAudio・全画面で共用） |
| `public/qr.js` | QR コードの生成（オフライン・依存なし） |
| `build-solo.js` | solo.html と共有 JS から単一ファイル版を生成（`node build-solo.js`） |
| `make-icons.js` | PWA アイコン PNG を依存なしで生成（`node make-icons.js`） |
| `seminar-timer-ipad.html` | 単一ファイル版（生成物。Android/Win/Mac 用。iPad は PWA を使う） |
| `.github/workflows/pages.yml` | `public/` を GitHub Pages(HTTPS) へ配信する CI（② のオフライン化用） |
| `start.command` | Finder からダブルクリックで起動（①） |
| `config.json` | 実行時に保存される設定（① 用・gitignore・端末ごと） |

追加パッケージはありません。Node.js（macOS）で動きます。Linux など他の環境でも `node server.js` で起動できます（macOS 固有なのはブラウザの自動起動と IP の自動検出くらいです）。
